#### 3.6.2 访问条件码

> 使用条件码的三类用途：  
> ① 设置字节  
> ② jump  
> ③ 传送数据

##### SET指令表

| 指令 | 同义名 | 效果 | 设置条件 |
|------|--------|------|----------|
| `sete D` | `setz` | `D ← ZF` | 相等/零 |
| `setne D` | `setnz` | `D ← ~ZF` | 不等/非零 |
| `sets D` | | `D ← SF` | 负数 |
| `setns D` | | `D ← ~SF` | 非负数 |
| `setg D` | `setnle` | `D ← ~(SF ⊕ OF) & ~ZF` | 大于（有符号>） |
| `setge D` | `setnl` | `D ← ~(SF ⊕ OF)` | 大于等于（有符号>=） |
| `setl D` | `setnge` | `D ← SF ⊕ OF` | 小于（有符号<） |
| `setle D` | `setng` | `D ← (SF ⊕ OF) \| ZF` | 小于等于（有符号<=） |
| `seta D` | `setnbe` | `D ← ~CF & ~ZF` | 超过（无符号>） |
| `setae D` | `setnb` | `D ← ~CF` | 超过或相等（无符号>=） |
| `setb D` | `setnae` | `D ← CF` | 低于（无符号<） |
| `setbe D` | `setna` | `D ← CF \| ZF` | 低于或相等（无符号<=） |

> 图3‑14 SET指令。每条指令根据条件码的某种组合，将一个字节设置为0或者1。有些指令有“同义名”，也就是同一条机器指令有别的名字。

> **SET语句只设置低8位字节，高位保持旧值！**

> 一条SET指令的目的操作数是低位单字节寄存器元素（图3‑2）之一，或是一个字节的内存位置，指令会将这个字节设置成0或者1。为了得到一个32位或64位结果，我们必须对高位清零。一个计算C语言表达式 `a < b` 的典型指令序列如下所示，这里a和b都是long类型：

> set → 单字节（8位）  
> 而常用寄存器多为64位 → set只能写入最低的单字节（`%al` / `%bl` 等）

```c
int comp(data_t a, data_t b)
a in %rdi, b in %rsi
```

```asm
comp:
    cmpq    %rsi, %rdi      # Compare a:b
    setl    %al             # Set low‑order byte of %eax to 0 or 1
    movzbl  %al, %eax       # Clear rest of %eax (and rest of %rax)
    ret
```

> 用 `movz` 零拓展高位置0

---

虽然所有的算术和逻辑操作都会设置条件码，但是各个SET命令的描述都适用的情况是：执行比较指令，根据计算 $t = a-b$ 设置条件码。更具体地说，假设 $a、b$ 和 $t$ 分别是变量a、b和t的补码形式表示的整数，因此 $t = a -_w b$，这里 $w$ 取决于a和b的大小。

#### 3.6.3 跳转指令

`jmp` 无条件跳转

- **直接跳转**：找代码中的标号目标
```asm
jmp .L1
.L1:
```

- **间接跳转**：指针寄存器或内存
```asm
jmp *%rax       # 取%rax内的地址
jmp *(%rax)     # 取(%rax)内存内的地址
```

> 程序执行是从内存逐个读取汇编命令，相当于读卡器。`jmp`后指向不同的卡口（即地址）  
> C中 `goto` 指向不同代码行，汇编下 `jmp` 指向不同内存，这些内存中放着待执行的命令。

#### 3.6.4 跳转指令的代码

跳转指令分为：  
1. 相对的用差值：1/2/4字节编码差值  
2. 绝对地址：4字节取址

| 偏移地址 | 指令字节编码 | 汇编指令及反汇编注释 |
|---------|-------------|---------------------|
| 0x0     | 48 89 f8    | mov %rdi,%rax       |
| 0x3     | eb 03       | jmp 0x8 <loop+0x8>  |
| 0x5     | 48 d1 f8    | sar %rax            |
| 0x8     | 48 85 c0    | test %rax,%rax      |
| 0xb     | 7f f8       | jg 0x5 <loop+0x5>   |
| 0xd     | f3 c3       | repz retq           |

> 右边反汇编器产生的注释中，第2行中跳转指令的跳转目标指明为0x8，第5行中跳转指令的跳转目标是0x5（反汇编器以十六进制格式给出所有的数字）。不过，观察指令的字节编码，会看到第一条跳转指令的目标编码（在第二个字节中）为0x03。把它加上下一条指令也就是下一条指令的地址，就得到跳转目标地址0x8，也就是第4行指令的地址。

> 编译器先找到 .L2、.L3这些点的位置，并记录下来。编译时，计算 .L2/.L3到目前下一条语句之间的距离。上例中，`8`处为目标位置，`3`处读取jmp。而由于执行时，指针已经到达jmp执行完后的`5`处，故计算 $8-5=3$，得出指针应移动3个长度，故而`eb 03`中写的是`03`。注释中跳到8处。`loop = 0`，因取相对地址。

✅ **程序计数器的值是跳转指令后面的那条指令的值**

#### 3.6.5 用条件控制来实现条件分支

> 类似 `if … else` 语句在机器代码中不存在，只用跳转指令改变执行顺序

执行流程：  
`不满足就跳转至else` → 满足时的then内容 → 无条件跳到else之后 → else块 → 之后内容

> 当然也可以是 "若条件为真就跳转"

#### 3.6.6 用条件传送来实现条件分支

先计算所有结果，再从2个结果中选择一个作为值。

1. 条件跳转（也称分支）的预测错误惩罚：处理器可重叠执行指令，取第N条时执行 N‑1的运算。

条件跳转不知道执不执行，故而进行**分支预测**，指前用会/不会跳转的结果，预测错误则会丢弃已有计算。

2. **条件传送**同时计算两个分支内容放于寄存器中，用 `cmovxx` 选择一个作最终值。

3. 条件传送**局限性**：两个分支可以被安全求值，例如，可能存在的空指针。

4. 性能权衡。条件传送同样会导致计算被浪费（两个分支中的一个），故而编译器应当在“浪费的计算”和“分支预测错误惩罚”之间进行权衡。
实验表明 GCC 只有在两个表达式都很容易计算时才会使用条件传送

5. 预测方法。例如“while”循环当然是循环为先。事实上，还有很多其他的方法，这很复杂，现代的预测大多追求90%以上的预测成功率
6. 条件传送限制：
计算的表达式安全（不为空指针，不除以0，不无效内存等）

两个分支的表达式都不能有副作用：不能修改内存、全局变量、I/O 状态等。因为两个表达式都会被计算，如果有副作用，两个副作用都会发生，违反程序语义。

计算代价不能太高：如果表达式很复杂（例如需要多条指令、函数调用等），即使条件不满足，也会花费大量时间计算另一个分支，可能得不偿失。编译器通常只在表达式非常简单（如单条指令）时才使用条件传送。

#### 3.6.8 switch语句

1. switch和if-else语句最大的区别是有时，编译器可以对switch语句优化产生**跳转表**，十分高效。
2. 跳转表操作：将case结果转化成数组，switch（n）转化成n个元素数组，存放n种不同情况的对位地址进行传送。
但是并非永远使用跳转表，在case数目较少，或者case值差异较大时，也可能使用二分查找等。
3. switch的穿透行为。没有break是，会从一个case穿透到下一个case，在汇编中，这个对应着缺少`jmp`，模拟着穿透行为。
4. 对于相同的case下代码，汇编也会用同一个Li优化，不同case值跳转到同一个内存中用同一块代码

#### 3.7.7运行时栈

1. 调用栈是因为我们会有函数调用过程，例如P调用Q，Q调用R。此时我们就需要挂起P过程，用栈更加匹配。
2. 栈是向低位增长的。这是因为在ram中，栈底部在ram最上方，而ram最下方放着代码块和数据，堆等
3. 栈的基本操作：
栈指针`%rsp`，用pushq，popq压入或者弹出数据。
可以通过调整栈指针分配或者释放空间。
分配空间：subq $n, %rsp 将栈指针减小 n 字节，相当于在栈上分配了 n 字节的空间（这些空间未初始化）。
释放空间：addq $n, %rsp 将栈指针增加 n 字节，相当于释放了之前分配的 n 字节空间。
4. 栈帧，用于储存过程的栈空间部分
栈上存储包含的内容有：返回地址，保存的寄存器的值，局部变量，为其他过程准备的参数（如果参数数目超过3个）
当前在使用的帧保持在栈顶。
5. 返回地址。当P调用Q时，call指令会吧返回地址压入栈中。
6. 栈帧长度：一般而言，栈帧是在过程开始时分配好大小，在编译时确定。但是对于变长数组或者alloca函数动态分配的空间，栈帧的大小在运行时才能够确定
7. 栈帧大小优化：系统只会按照最少需要设置栈帧。对于一些过程会省略，例如
> 参数数目较少，少于6，会直接用寄存器传递
> 如果该过程不调用其他函数（称为**叶子过程**）则不需要任何栈帧。
