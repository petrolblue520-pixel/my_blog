> set → 单字节（8位）  
> 而常用寄存器多为64位 → set只能写入最低的单字节（`%al` / `%bl` 等）

```c
int comp(data_t a, data_t b)
a in %rdi, b in %rsi
```

```asm
comp:
    cmpq    %rsi, %rdi      # Compare a:b
    setl    %al             # Set low‑order byte of %eax to 0 or 1
```

#### 3.6.3 跳转指令

`jmp` 无条件跳转

- **直接跳转**：找代码中的标号目标
```asm
jmp .L1
.L1:
```

- **间接跳转**：指针寄存器或内存
```asm
jmp *%rax       # 取%rax内的地址
jmp *(%rax)     # 取(%rax)内存内的地址
```

> 程序执行是从内存逐个读取汇编命令，相当于读卡器。`jmp`后指向不同的卡口（即地址）  
> C中 `goto` 指向不同代码行，汇编下 `jmp` 指向不同内存，这些内存中放着待执行的命令。

#### 3.6.4 跳转指令的代码

跳转指令分为：  
1. 相对的用差值：1/2/4字节编码差值  
2. 绝对地址：4字节取址

| 偏移地址 | 指令字节编码 | 汇编指令及反汇编注释 |
|---------|-------------|---------------------|
| 0x0     | 48 89 f8    | mov %rdi,%rax       |
| 0x3     | eb 03       | jmp 0x8 <loop+0x8>  |
| 0x5     | 48 d1 f8    | sar %rax            |
| 0x8     | 48 85 c0    | test %rax,%rax      |
| 0xb     | 7f f8       | jg 0x5 <loop+0x5>   |
| 0xd     | f3 c3       | repz retq           |

> 右边反汇编器产生的注释中，第2行中跳转指令的跳转目标指明为0x8，第5行中跳转指令的跳转目标是0x5（反汇编器以十六进制格式给出所有的数字）。不过，观察指令的字节编码，会看到第一条跳转指令的目标编码（在第二个字节中）为0x03。把它加上下一条指令也就是下一条指令的地址，就得到跳转目标地址0x8，也就是第4行指令的地址。

> 编译器先找到 .L2、.L3这些点的位置，并记录下来。编译时，计算 .L2/.L3到目前下一条语句之间的距离。上例中，`8`处为目标位置，`3`处读取jmp。而由于执行时，指针已经到达jmp执行完后的`5`处，故计算 $8-5=3$，得出指针应移动3个长度，故而`eb 03`中写的是`03`。注释中跳到8处。`loop = 0`，因取相对地址。

✅ **程序计数器的值是跳转指令后面的那条指令的值**

#### 3.6.6 用条件传送来实现条件分支

先计算所有结果，再从2个结果中选择一个作为值。

1. 条件跳转（也称分支）的预测错误惩罚：处理器可重叠执行指令，取第N条时执行 N‑1的运算。

条件跳转不知道执不执行，故而进行**分支预测**，指前用会/不会跳转的结果，预测错误则会丢弃已有计算。

2. **条件传送**同时计算两个分支内容放于寄存器中，用 `cmovxx` 选择一个作最终值。

3. 条件传送**局限性**：两个分支可以被安全求值，例如，可能存在的空指针。

4. 性能权衡。条件传送同样会导致计算被浪费（两个分支中的一个），故而编译器应当在“浪费的计算”和“分支预测错误惩罚”之间进行权衡。
实验表明 GCC 只有在两个表达式都很容易计算时才会使用条件传送

5. 预测方法。例如“while”循环当然是循环为先。事实上，还有很多其他的方法，这很复杂，现代的预测大多追求90%以上的预测成功率
6. 条件传送限制：
计算的表达式安全（不为空指针，不除以0，不无效内存等）

两个分支的表达式都不能有副作用：不能修改内存、全局变量、I/O 状态等。因为两个表达式都会被计算，如果有副作用，两个副作用都会发生，违反程序语义。

计算代价不能太高：如果表达式很复杂（例如需要多条指令、函数调用等），即使条件不满足，也会花费大量时间计算另一个分支，可能得不偿失。编译器通常只在表达式非常简单（如单条指令）时才使用条件传送。

#### 3.6.8 switch语句

1. switch和if-else语句最大的区别是有时，编译器可以对switch语句优化产生**跳转表**，十分高效。
2. 跳转表操作：将case结果转化成数组，switch（n）转化成n个元素数组，存放n种不同情况的对位地址进行传送。
但是并非永远使用跳转表，在case数目较少，或者case值差异较大时，也可能使用二分查找等。
3. switch的穿透行为。没有break是，会从一个case穿透到下一个case，在汇编中，这个对应着缺少`jmp`，模拟着穿透行为。
4. 对于相同的case下代码，汇编也会用同一个Li优化，不同case值跳转到同一个内存中用同一块代码

### 3.7 过程

#### 3.7.1 运行时栈

1. 调用栈是因为我们会有函数调用过程，例如P调用Q，Q调用R。此时我们就需要挂起P过程，用栈更加匹配。
2. 栈是向低位增长的。这是因为在ram中，栈底部在ram最上方，而ram最下方放着代码块和数据，堆等
3. 栈的基本操作：
栈指针`%rsp`，用pushq，popq压入或者弹出数据。
可以通过调整栈指针分配或者释放空间。
分配空间：subq $n, %rsp 将栈指针减小 n 字节，相当于在栈上分配了 n 字节的空间（这些空间未初始化）。
释放空间：addq $n, %rsp 将栈指针增加 n 字节，相当于释放了之前分配的 n 字节空间。
4. 栈帧，用于储存过程的栈空间部分
栈上存储包含的内容有：返回地址，保存的寄存器的值，局部变量，为其他过程准备的参数（如果参数数目超过3个）
当前在使用的帧保持在栈顶。
5. 返回地址。当P调用Q时，call指令会吧返回地址压入栈中。
6. 栈帧长度：一般而言，栈帧是在过程开始时分配好大小，在编译时确定。但是对于变长数组或者alloca函数动态分配的空间，栈帧的大小在运行时才能够确定
7. 栈帧大小优化：系统只会按照最少需要设置栈帧。对于一些过程会省略，例如
> 参数数目较少，少于6，会直接用寄存器传递
> 如果该过程不调用其他函数（称为**叶子过程**）则不需要任何栈帧。

####  3.7.2 转移控制

1. 面对过程中遇到的转移问题，我们需要解决两个部分。进入Q和返回P
2. **call**命令调用过程，like
`call label`用于直接掉用，目标地址是标号
`call *operand`用于间接调用，目标地址从寄存器或者内存中读。like call *%rax（用rax内部的值），call *(%rax)（用rax的值先找到内存，从内存中读取目标地址）
`ret`从过程调用中返回
3. call的执行：为了返回，call先会将call**之后**的那条地址作为返回地址压入栈中，然后再跳转到调用的过程的起始地址。
4. 为什么我们必须用一个栈而非寄存器：一旦出现**嵌套调用**，一个寄存器是完全不够的，出现嵌套调用更加符合栈的含义，用栈更好。

#### 3.7.3 数据传送

1. 大部分依赖寄存器，寄存器不够用栈。寄存器有6个用于储存参数，多了放栈
2. 栈传参特点。不论类型用8字节对齐。第七个参数，也就是第一个放入栈的。位于栈顶。
第一个%rsp,第二个%rsp+8
3. 寄存器注意：根据类型不同，大小不同用不同的寄存器部分，%rdi %edi %di % dil

#### 3.7.4 栈上的局部存储

本节内容主要探讨的是，为什么有些数据不能只放在寄存器里，而必须放在栈上，以及如何通过栈帧来管理这些局部数据。
1. 为什么局部数据必须放在内存上？有三种情况：
   1. 寄存器不够用。
   2. 对局部变量使用了地址运算符。对于局部变量使用地址运算符的原因是因为它要求需要有一个真实的内存地址，但寄存器是没有地址的。
   3. 局部变量是数组或者是结构体。如果是数组或者是结构体的话，这样的局部变量较大，因此我们需要将它放到栈上。

2. 控制栈帧的分配与释放。栈帧指针我们通过 `%RSP` 来分配或者是释放。执行 `SUBQ $N, %RSP`，我们可以让栈帧指针向下移动 N 个字节，从而开辟空间。使用 `ADDQ` 则可以让栈指针上移，从而恢复到原来的位置，相当于减少栈的空间。

#### 3.7.5 寄存器中的局部存储空间

首先，寄存器是所有函数共用的。因此，一旦有某一个函数修改了寄存器的内容之后，可能会导致刚刚调用的那个函数所需要的值丢失。因此，我们需要一个完善的寄存器保管惯例，用于协调寄存器的使用。

1. 寄存器的两种类型  
   1. 被调用者保存寄存器，这些寄存器包括 `%rbx`、`%rbp` 和 `%r12` 到 `%r15`。它要求是被调用者 Q 在执行调用时，先把寄存器中的内容记录下来，再返回时恢复寄存器的内容。  
   2. 调用者保存寄存器，除了栈指针 `%rsp` 以及被调用者保存寄存器外，所有的寄存器都属于这一类。在 Q 调用 P 用过的寄存器的这种情况之下，P 需要自己保存寄存器的内容，这意味着这类寄存器可以被任意的函数随意地修改。

2. 保存与恢复的典型实现  
   被调用者保存和恢复寄存器最常见的方法是通过栈。将旧值压入栈中，再返回时再恢复原始值。

#### 3.7.6 递归过程

递归调用的函数与普通函数调用之间没有任何区别。递归能够正常工作依赖三个机制：每个调用的独立栈帧、寄存器的保存惯例使得调用者的数据不会被破坏，栈的后进先出特性与递归调用的顺序匹配。

3.8 节主要了解数组访问如何从下标变成地址运算，以及编译器在不同情况下如何对其进行优化。

#### 3.8.1 基本原则

1. 数组地址的核心公式：$$地址 = X_A + L \times i$$，其中 $X_A$  是数组的起始地址，$L$ 是数组元素的大小（以字节为单位），$i$ 是下标。

2. 机器代码中访问数组元素使用的是基地址加下标乘以伸缩因子的计算。例如 int 类型的数组访问，访问 E[i] 的指令：`MOVL (%RDX, %RCX, 4), %EAX`。地址计算为 `%RDX + 4 * %RCX = X_E + 4i`（数组 E 是 int 类型，起始地址放在寄存器 `%RDX` 中）。

3. 伸缩因子可以是 1、2、4、8，分别对应基本数据类型的大小：char（1）、short（2）、int 或 float（4）、long 或 double 和指针（8）。

#### 3.8.3 嵌套数组

1. 嵌套数组就是二维数组，或者是更高维的三维、四维等等的数组。

2. 声明一个数组 `T D[R][C]`，其数组元素 `D[i][j]` 的内存地址为：$$\&D[i][j] = X_D + L \times (C \times i + j)$$，其中 L 是数据类型 T 以字节为单位的大小。

3. 嵌套数组（如二维数组）默认按行优先存储（C/C++等采用），但存储顺序与语言种类有关，并非所有语言都采用行优先。例如：
   - 行优先（Row-major）：最右边的下标变化最快，如 C、C++、Pascal、Python（NumPy 默认）等。
   - 列优先（Column-major）：最左边的下标变化最快，如 Fortran、MATLAB、R 等。
   - Java 比较特殊：Java 没有真正的多维数组，而是“数组的数组”（Array of Arrays）。每个子数组都是独立的对象，在内存中并不是一整块连续的空间。因此从严格的内存布局来说，Java 既不是纯粹的行优先也不是列优先；但从逻辑访问顺序（外层数组视为行、内层数组视为列）来看，通常可以按行优先来理解和使用。

#### 3.8.4 定长数组

对于二维数组，访问某个元素通常需要乘法计算偏移量。但在遍历数组时，编译器可以利用数组元素在内存中连续存放的特性，通过指针递增（即加法操作）来替代乘法，从而优化性能。

#### 3.8.5 变长数组

1. 定长数组在循环遍历时（如 `for (int i = 0; i < n; i++)`），编译器可以不用保存变量 `i`，也无需执行 `i` 的自增操作。取而代之的是，通过比较当前指针和数组末尾指针是否相等来判断循环结束。

2. 计算数组结束的地址需要乘法操作。定长数组可以使用 `LEAQ` 指令快速计算出结果，而变长数组则必须使用真正的乘法指令，这对性能影响较大。

3. 由于乘法开销较大，GCC 在处理变长数组的遍历时，不会采用指针是否到达末尾的方式来判断循环结束，而是通过检查变量 `i` 是否达到 `n` 来控制循环。

4. 保留变量 `i` 的方式会引入两项额外操作：检查 `i < n` 和 `i` 的自增。编译器在优化时会尽量减少多余操作。定长数组可以完全省去维护 `i` 的开销，而变长数组为了避免乘法，则必须保留 `i` 作为循环控制变量。

### 3.9 异质的数据结构

本节解决的核心问题：内存布局、字段访问、空间浪费（对齐）、联合陷阱和用途。

| 小节 | 核心内容 | 解决的问题 |
|------|---------|-----------|
| 3.9.1 结构 | 结构的内存布局、字段偏移、访问字段的汇编代码、嵌套结构、结构指针 | 如何把多个不同类型字段连续摆放并高效访问它们 |
| 3.9.2 联合 | 联合的内存共享、大小计算、应用场景（节省空间、未定义模式访问、字节序问题） | 如何让多个类型复用同一个内存，以及这种复用的利弊 |

#### 3.9.1 结构

结构体的字段按照声明顺序在内存中依次排列。每个字段的起始偏移量由前面字段的大小和当前字段的对齐要求共同决定（对齐规则详见 3.9.3）。访问结构体字段时，编译器通过基地址加偏移量生成汇编代码。

#### 3.9.2 联合

1. 联合（Union）的所有字段从同一个内存地址开始，共享同一块内存。其总大小由最大的字段决定。

2. 使用联合时，无法直接知道当前内存中存储的数据是什么类型，只能明确所有字段的位表示是相同的。

3. 浮点数和普通整数在位表示上完全不同。如果使用指针强制转换（如将 `double` 转换为 `unsigned`），会进行数值截断（例如 `1.5` 转为 `1`）。但如果通过联合同时定义 `double` 和 `unsigned` 字段，向 `double` 字段写入值后，再以 `unsigned` 字段读取，则会按照 `unsigned` 的位编码解释该内存中的字节序列，得到的是位模式对应的整数，而不是截断后的数值。

#### 3.9.3 数据对齐

1. 数据对齐要求某种类型对象的地址必须是某个值（通常是 2、4、8）的倍数。这样的对齐限制简化了处理器和内存系统之间接口的硬件设计。

2. 例如有如下结构体 `S1`：
   `struct S1 { int i; char c; int j; };`
   假设编译器用最小的 9 字节分配，则 `int j` 的字节偏移将从 5 开始，不满足 4 的倍数。因此会在 `c` 和 `j` 之间填充空余空间，使得 `j` 的地址偏移为 8，整个结构体的大小变为 12 个字节。

### 3.10

#### 3.10.1 理解指针

指针也可以指向函数。例如有如下函数原型定义：
```c
int function(int x, int *p);
```
可以声明一个指针 `fp` 并将其赋值为该函数：
```c
int (*fp)(int, int *);
fp = function;
```
然后用该指针调用函数：
```c
int y = 1;
int result = fp(3, &y);
```

#### 3.10.3 内存越界引用和缓冲区溢出

1. 通常在栈中分配某个字符数组来保存字符串，但如果字符串长度超出了为数组分配的空间，则会发生溢出。例如 `gets` 函数会直接读取一整行的所有内容，而不考虑数组的大小，极易导致缓冲区溢出。

2. 从机器层面理解，缓冲区溢出会破坏栈帧结构，可能覆盖调用者的栈帧数据，尤其是返回地址，从而导致程序崩溃或产生不可预知的行为。

3. 缓冲区溢出的一个更严重的利用方式，是让程序执行它原本不会执行的代码。攻击者可通过覆盖栈中的返回地址，使其指向一段恶意代码（或攻击代码的起始位置），当函数执行 `ret` 指令时，程序便会跳转到该地址，从而执行攻击代码。

#### 3.10.4 对抗缓冲区溢出攻击

##### 栈随机化

1. 安全单一化：在过去，程序的栈地址非常容易预测，因为对于所有运行同样程序和操作系统版本的系统来说，栈的位置相对固定，导致许多系统容易受到同一种攻击，这种现象被称为“安全单一化”。

2. 栈随机化的思想：在程序开始之前，在栈上先分配一段 0 到 n 字节的随机大小的空间，从而使程序每次执行后的栈地址发生变化，不易被预测。

3. 在 Linux 系统中，栈随机化已成为标准行为，该技术称为地址空间布局随机化（ASLR），使得每次运行时程序的不同部分（包括程序代码、库代码、栈、全局变量和堆数据）都会被加载到内存的不同区域。

4. 事实上，局部变量的地址在 Linux 上运行时也有一定的变化范围：32 位 Linux 上范围大小为 \(2^{23}\)，64 位 Linux 上范围为 \(2^{32}\)。因此攻击者如果枚举地址，仍有可能成功。ASLR 能够增加攻击难度，大大降低病毒或蠕虫的传播速度，但不能提供完全的安全保障。

##### 栈破坏检测

1. 栈保护者机制：在栈中任何局部缓冲区与栈状态之间存储一个特殊的“金丝雀值”（也称哨兵值）。该值完全随机，在程序运行时产生。在恢复寄存器状态和从函数返回之前，程序检查金丝雀值是否被改变，若被改变则程序终止。

2. 金丝雀值是通过段寻址从内存中读入的。

##### 限制可执行代码区域

限制哪些内存区域能够存放可执行代码。例如 AMD 为其 64 位处理器内存保护引入了 NX（No Execute，不执行）位，将读和执行访问模式隔开。

#### 3.10.5 支持变长栈帧

1. 普通定长栈帧使用 `%rsp` 作为栈指针来固定，回退时直接根据 `%rsp` 的位置即可恢复。

2. 对于变长栈帧，由于在编译时无法确定栈帧大小，无法事先知道返回地址的固定偏移，因此需要使用 `%rbp` 来记录当前栈帧的基准位置，以便在函数返回时正确恢复。

3. 为什么不通过计算 `%rsp` 的移动量来回退？因为变长大小在运行时才能确定，若要记录并计算 `%rsp` 总共移动了多少字节，涉及多次运算和保存，实现复杂且容易出错。使用 `%rbp` 作为固定基准更简单可靠。

> 使用 `%rbp` 的四个原因：
> 
> 第一，X86 指令集中为栈帧退出设计了 `leave` 指令，仅需一个字节的机器码、一个时钟周期即可完成栈帧销毁。
> 
> 第二，在程序崩溃或异常时，调试器（如 GDB）需要反向遍历调用栈（栈回溯），使用 `%rbp` 可以构成链表结构，使栈回溯更加清晰明确。
> 
> 第三，变长栈帧中 `%rsp` 可能会多次分配和移动，如果通过记录并计算 `%rsp` 的移动长度来回退，计算逻辑复杂且极易出错。使用 `%rbp` 固定基准可避免这一问题。
> 
> 第四，`%rbp` 属于被调用者保存寄存器，只需在开头 `push %rbp`、结尾 `pop %rbp` 即可保证不破坏调用者的数据。若采用记录偏移量的方法，则需要额外占用一个非易失的通用寄存器来保存该偏移量，占用寄存器资源。
